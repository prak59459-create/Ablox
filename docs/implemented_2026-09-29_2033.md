# Ablox 実装済み機能まとめ

最終更新: 2026-09-29 20:33（日本時間）

Ablox（遊ぶアプリ）、Ablox Studio（作るアプリ）、abloxgames（ゲーム一覧）の3つのリポジトリで、ここまでに作ったものをまとめました。

- 作業ブランチ: `claude/ablox-ipad-platform-8e8d8m`（3つとも）。abloxgames は `main` にも反映済み。
- バージョン: **Ablox 1.6（ビルド 5）**、**Ablox Studio 1.5（ビルド 6）**。プッシュするたびに 0.1 ずつ上げています（「バージョンの上げ方」の章）。
- テスト: Ablox 846件、Studio 998件、すべて成功（Linux 上で実行。画面や 3D の部分は iPad でしか確かめられません。iOS 向けのビルドは毎回 GitHub の Mac で通しています）。
- 印の意味: ✅ 完了してプッシュ済み ／ 🚧 作業中 ／ ⚠️ 形を変えて実現（理由は最後の章）

## 直したこと

### BSActionErrorDomain（1.6）

- **クリップ（最後の30秒を残す）で BSActionErrorDomain エラーが出る**: クリップは iPadOS の録画機能（ReplayKit）を使っていて、始めるときに iPadOS が「録画してもいいか」を聞きます。Swift Playgrounds から動かすアプリではこの質問を出せず、iPadOS が BSActionErrorDomain というエラーを返し、それがポーズメニューにそのまま出ていました。クリップは一度も始まっていませんでした。
  - 直し方: ReplayKit をやめて、Ablox が自分で記録するようにしました。3D の画面（ワールドの見た目の効果もそのまま、ボタンや文字はなし）を1秒30コマ・長い辺1280ピクセルで、ゲームの音といっしょに10秒ずつのファイルに書き、保存するときに最後の30秒をつなげます。許可の質問はなく、どこにも送りません。ゲームを出ると記録は止まり、ファイルは消えます。
  - クリップのお知らせは、システムのエラーコードではなく「まだ保存できるものがありません…」のような言葉で出ます。
- **「iPadの設定アプリのAblox」ボタン**: Swift Playgrounds から動かすアプリには自分の設定ページがないので、iPadOS が開くのを断ることがあります。そのときは何も起きなかったのを、「設定アプリを自分で開いて Swift Playgrounds の項目を見てください」と出すようにしました。

### 500機能のあいだに見つけて直したこと

- **スクリプトでアプリごと止まることがあった**: リストの位置や個数、桁数に `nan`（`sqrt(-1)` など）やとても大きな数（`pow(10, 300)`）を使うと、`list[…]`・`insert`・`remove`・`slice`・`range`・`round`・`fixed`・`random`・`cancel`・アイテムの数・ショップの値段・弾の数などで、スクリプトのエラーではなくアプリ全体が止まっていました。どれも安全な数に直すか「大きすぎる」エラーにしました（Studio のテストプレイも同じ）。テストで確かめています。
- **一時停止中の変数表示**: 関数と同じ名前の自分の変数（`count`、`first` など）が、ブレークポイントで止まったときに表示されませんでした。表示するようにしました。
- **ぼうし**: 買わなくてもかぶれていたのを、買ってからにしました（N）。

### それより前に直したこと


- **ゲームがポップアップで開く**: ゲームのページ・友だち・招待・「ホストとして遊ぶ」の確認など、シートの中のボタンから始めると、そのシートが閉じきる前にフル画面のゲームを出していました。そのため、フル画面にならず閉じかけのシートの中に出たり、出なかったりしていました。すべての入口を1か所にまとめ、画面の上のシートが閉じきってから（約0.3秒）フル画面で開くようにしました。連打しても2回開きません。Studio のエディタ（AI マップ・新規作成・参加）も同じ直し方です。
- 「今は遊べません」のお知らせも、シートが閉じてから出すようにしました（シートの上に出して見えないことがあった）。
- ゲーム後のまとめと「新しいバージョンのお知らせ」が同時に出ようとしてぶつからないようにしました。
- **一覧のゲーム9本が途中で止まる**（全80本を自動でプレイして見つけました）: #1 Maple Bay Life RP、#3 Pet Home Paradise、#7 Sprout Garden、#13 Hotel 100 Doors、#16 Crystal Wars、#34 Cherry Lane RP、#36 Neo City Life、#55 Endless Rooms、#65 Critter Quest。これらのゲームはプレイヤーに `p.items = {}` のように自分のデータを入れていますが、あとから同じ名前（`items`・`vehicle`・`shop`）の機能を追加したため、「関数です」というエラーで止まっていました。あとから追加した名前には、ゲームが自分のデータを入れてよいことにして直しました（ゲーム側は変えていないので、自作のゲームも同じように直ります）。ほかの名前は今までどおり守られます。
- **スクリプトの色付け**: `#` のコメント、`'…'` や日本語キーボードの `“…”` の文字列が色付けされず、その中の `--` がコメントの色になっていました。言語の読み方と同じに直しました。

## iPad でのビルドについて

- **以前**: iPad 第9世代で1回6分ほどかかり、3回目で起動（計18分ほど）。原因はメモリ不足とみています。約46,000行を1つのモジュールとしてビルドしていたので、コンパイルの各ジョブがアプリ全体を抱えていました。
- **今回やったこと**（機能・見た目は削っていません）:
  1. **2つのモジュールに分割**: 土台の `AbloxCore`（Studio は `EditorCore` も含む）と、アプリ本体。各ジョブが自分のモジュールの分だけを持つので、メモリの山が小さくなります。
  2. **土台は Foundation だけを読み込む**: 土台の中に SwiftUI・RealityKit・UIKit を読み込むファイルが1つあり、そのせいで土台の全ジョブが重いフレームワークを読み込んでいました。そのファイルを Engine に移しました。
  3. **コンパイルが遅い部分を分割**: ゲーム詳細、セーブデータ、プレイ画面、保護者設定、ショップ、投票、空の描画、ジェスチャー、素材、パーティクル、吹き出し、Studio の差分表示・ブロックカード・ツールバーなど。表示や動きは変わりません。
- **測定**（GitHub の Mac で iOS 向けにビルド。計測用の設定込みなので実際より遅めです）:

| | ビルド全体 | Swift コンパイル合計 | 型チェック合計 |
|---|---|---|---|
| 分割した直後（土台がまだ SwiftUI などを読み込む） | 140秒 | 204秒 | 76秒 |
| 土台を Foundation だけに | 95秒 | 116秒 | 29秒 |

- **iPad がいつもビルドする状態で測り直しました**（同じ Mac で続けて）:

| | ビルド全体 |
|---|---|
| 1回目（iOS 自体の部品の下準備から） | 77秒 |
| 2回目以降の状態で最初から全部 | 34〜40秒 |
| 同じ、デバッグ情報なし（今回入れました） | 28〜31秒 |

  iOS 自体の部品（UIKit、SwiftUI など）の下準備は、iPad では一度済めば残ります。なので、ふだんのビルドは表の2行目の状態です。
- **ほかにしたこと**: `#Preview`（開発用のプレビュー）を外しました。ビルド中にプラグインを動かす必要があり、遊ぶ人には見えないものです。以後、マクロは使わないようにチェックしています。Studio のインスペクタも軽くしました。
- **デバッグ情報なし（`-Xfrontend -gnone`）を入れました**: Mac の測定では15〜20%速くなります。最初は `-gnone` だけで入れましたが効いていませんでした（Xcode がその後ろに自分の `-g` を付けるため）。そこでコンパイラ本体に直接渡す形にし、デバッグ情報が消えたことを CI で確認しました（生成物 48.8 MB → 34.9 MB）。Package.swift の `unsafeFlags` を Swift Playgrounds が受け付けるかは、iPad で開いて確かめるまで分かりません。開けなかったときは、そのメッセージを送ってください。2行を消せば元に戻ります。
- **更新を「変わったファイルだけ」で入れられるように**（設定 → アップデート）: 新しい版を新しいプロジェクトとして入れると、毎回アプリ全体（約46,000行）をビルドし直します。そこで、この iPad にある Ablox のプロジェクトを一度ファイルで選んでおけば、新しい版は**変わったファイルだけ**をそのプロジェクトに書き込むようにしました。Swift Playgrounds は変わったところだけをビルドし直すので、数ファイルの更新なら数秒〜十数秒で済むはずです。
  - 触るのは `Package.swift` と `Sources/` だけです。Playgrounds の設定で選んだアイコンは残ります。Studio のプロジェクトに Ablox を書き込むような間違いは止めます。
  - 「公開前の版を試すとき」にブランチ名（例: `claude/ablox-ipad-platform-8e8d8m`）を入れて「今の最新を取り込む」を押すと、そのブランチの最新がバージョン番号に関係なく入ります。
  - まだ iPad では試していません（Playgrounds がアプリからの書き込みを受け付けるか、変わったファイルだけビルドするか）。
- **20秒について**: 約46,000行を最初から全部ビルドする限り、iPad 第9世代で20秒は難しいです。変更したファイルだけを作り直す2回目以降は、ずっと短くなるはずです。
- **iPad で確認済み**: 2つのモジュールに分けたプロジェクトは Swift Playgrounds で開けました。
- **Studio**: 今回はじめて Mac で iOS 向けにビルドし、前からあったビルドエラーを2つ（地図アシスタント、公開シート）見つけて直しました。
- ビルド前にほかのアプリを閉じると、途中で止まりにくくなります。
- 以前に直したビルドエラー: `Gesture` の名前の衝突（PlayScreen）、メインアクター外からの `wallet` 参照（アバター画面）、警告2件。

## お知らせの出し方（156）

Ablox リポジトリのいちばん上にある `notices.json` を編集してプッシュすると、数時間以内に各 iPad のメインメニューに出ます。

```json
{"notices": [
  {"id": "毎回ちがう名前", "kind": "info か event か warning",
   "title": {"en": "英語の題", "ja": "日本語の題"},
   "body": {"en": "本文", "ja": "本文"},
   "from": "2026-10-01", "until": "2026-10-31"}
]}
```

`from` / `until`（表示する期間）、`minVersion` / `maxVersion`（対象のバージョン）、`app`（"Ablox" か "Ablox Studio"）は省略できます。
