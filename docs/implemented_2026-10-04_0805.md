# Ablox 実装済み機能まとめ

最終更新: 2026-10-04 08:05（日本時間）

Ablox（遊ぶアプリ）、Ablox Studio（作るアプリ）、abloxgames（ゲーム一覧）の3つのリポジトリで、ここまでに作ったものをまとめました。

- 作業ブランチ: `claude/ablox-ipad-platform-8e8d8m`（3つとも）。abloxgames は `main` にも反映済み。
- バージョン: **Ablox 3.1（ビルド 20）**、**Ablox Studio 2.9（ビルド 20）**。プッシュするたびに 0.1 ずつ上げています（「バージョンの上げ方」の章）。
- テスト: Ablox 892件、Studio 1044件（うち3件はこの環境では飛ばすもの）、すべて成功（Linux 上で実行。画面や 3D の部分は iPad でしか確かめられません。iOS 向けのビルドは毎回 GitHub の Mac で通しています）。
- 印の意味: ✅ 完了してプッシュ済み ／ 🚧 作業中 ／ ⚠️ 形を変えて実現（理由は最後の章）

## Z6. どんなときも 30〜60fps を（Ablox 2.6 ／ Studio 2.4）

「もっと軽くして、何があっても 30〜60fps 出るように。クオリティと FPS を両立して」というお願いから。
見た目を落とさずに速くするため、iPad が「1フレームに何をしているか」を ひとつずつ 調べて直しました。

| | 内容 |
|---|---|
| ✅ | **動かないパーツを まとめて描く**: iPad はパーツ1つごとに（影でもう1回）描く手間がかかり、パーツの数が多いと それだけで重くなっていました。動かないパーツを「48m 四方 × 色と素材」ごとに 1つの形に まとめ、キャラクターのパーツは キャラごと・色ごとに まとめます（キャラが歩けば いっしょに動く）。形は ふだん使っている形を そのまま使うので、**見た目は まったく同じ** です（`StillPartBaker`、`RenderMerging`） |
| ✅ | まとめたパーツが 変わったら（色・位置・見える/見えない・スクリプトの色変え や 移動）、すぐ まとめから外して 1つで描く。作りなおしが できるまでは 前の形で描くので、2重に見えたり 1フレーム消えたり しない。何度も変わるパーツは まとめに もどすのを だんだん 待つ（8秒→16秒→… 最大2分） |
| ✅ | 名前・タグ・スコアが変わっただけなら まとめから外さない。すけて見えない根っこ（キャラクターの中心）は そもそも描かない |
| ✅ | **ゲームが ワールドを変えるたびに 画面ぜんぶを作りなおしていた**のを やめた: 変更は その場で当てて、どのブロックが変わったかを メモ（`WorldChangeLog`）。3D の画面は そのブロックだけを見る。ボタンなどの画面に知らせるのは 1秒に10回まで（`PublishThrottle`）。消えたブロックも 全部を見なおさずに 外す |
| ✅ | **ホストのスクリプトが 最大30倍速く**: スクリプトがブロックを1つ動かすたびに、ワールドの全ブロックを くらべていました（3000パーツ・60体が歩くワールドで 1ステップ 230ミリ秒 → 7ミリ秒）。変わったブロックを記録する「日記」（`BlockJournal`）と、ブロックをすぐ見つける表（`BlockOrders`）を追加 |
| ✅ | **「自動」は まず解像度を少しだけ下げる**: 50fps を下回ったら 5%ずつ（最低 80%）。影や丸い形は そのまま 60fps をねらい、速くなったら 解像度を もどす。16fps を下回った1秒は すぐ 1段下げる |
| ✅ | ブロックの上の文字・自分で動くブロックは 1秒に4回 近いものを探し、近い数十個だけを 毎フレーム動かす（画質ごとに 数と距離が決まっている） |
| ✅ | 動く床のあるワールドで 毎フレーム ワールドぜんぶを コピーしていたのを やめた |
| ✅ | 起動チェック（Mac の CI）に「ベンチマーク」を追加: 3000パーツ・60体が歩くワールドに入り、1秒ごとの fps・画質・まとめた数を表示（`RenderBenchmark`、`-AbloxPlayBenchmark YES`） |
| ✅ | テスト: まとめる形の向き・位置・模様のくり返し、まとめてよいパーツ、変更メモ、日記と表（コピーしたワールドでも まちがえない）、自動の解像度、ベンチマークのワールドとスクリプト |

## 直したこと

### 起動してすぐ止まる（1.7）

- **症状**: Swift Playgrounds で「Ablox がクラッシュしました」（BSActionErrorDomain エラー1 や XPC error）が出て、起動すらできませんでした。
- **原因**: プレイタブの「貯金ビン」カードのスライダーです。コインが10〜19枚で貯金ビンが空のとき、スライダーの両はしが「10〜10」になり、SwiftUI がそれをアプリを止める誤りとして扱います（`max stride must be positive`）。プレイタブは最初に出る画面なので、毎回起動した瞬間に止まっていました。新しく始めた人は最初の日のボーナスでちょうどこの枚数になります。
- **直し方**: 両はしが同じになるときはスライダーを出さず、入れる／出す量は持っている分に収めます（`CoinJar.sliderTop` と `CoinJar.chosen`、0〜200枚のすべてでテスト）。ほかのスライダーはすべて範囲が決まっていて、同じことは起きません。
- **見つけ方と、これから**: GitHub の Mac で、iPad のシミュレータに実際にアプリを入れて起動するチェック（Launch check）を作りました。起動して30秒見守り、落ちたらその理由（Swift のエラーの文とクラッシュした場所）を出します。さらに、ゲーム・ワールド・アバター・ショップ・設定の各タブを1つずつ開いて確かめます。Ablox と Studio の両方で、プッシュのたびに動きます。
  - ⚠️ このチェックで分かるのは、はじめて入れた状態で起動して、各タブの最初の画面を開くところまでです。iPad に残っている前のデータや、ボタンを押したあとの画面までは確かめられません。
- 前回（1.6）の「BSActionErrorDomain はクリップのせい」という見立ては外れていました。そのとき作ったクリップの自前記録は、それはそれで Playgrounds でも使えるようになる直しなので残しています。

### BSActionErrorDomain（1.6）

- **クリップ（最後の30秒を残す）で BSActionErrorDomain エラーが出る**: クリップは iPadOS の録画機能（ReplayKit）を使っていて、始めるときに iPadOS が「録画してもいいか」を聞きます。Swift Playgrounds から動かすアプリではこの質問を出せず、iPadOS が BSActionErrorDomain というエラーを返し、それがポーズメニューにそのまま出ていました。クリップは一度も始まっていませんでした。
  - 直し方: ReplayKit をやめて、Ablox が自分で記録するようにしました。3D の画面（ワールドの見た目の効果もそのまま、ボタンや文字はなし）を1秒30コマ・長い辺1280ピクセルで、ゲームの音といっしょに10秒ずつのファイルに書き、保存するときに最後の30秒をつなげます。許可の質問はなく、どこにも送りません。ゲームを出ると記録は止まり、ファイルは消えます。
  - クリップのお知らせは、システムのエラーコードではなく「まだ保存できるものがありません…」のような言葉で出ます。
- **「iPadの設定アプリのAblox」ボタン**: Swift Playgrounds から動かすアプリには自分の設定ページがないので、iPadOS が開くのを断ることがあります。そのときは何も起きなかったのを、「設定アプリを自分で開いて Swift Playgrounds の項目を見てください」と出すようにしました。

### 500機能のあいだに見つけて直したこと

- **スクリプトでアプリごと止まることがあった**: リストの位置や個数、桁数に `nan`（`sqrt(-1)` など）やとても大きな数（`pow(10, 300)`）を使うと、`list[…]`・`insert`・`remove`・`slice`・`range`・`round`・`fixed`・`random`・`cancel`・アイテムの数・ショップの値段・弾の数などで、スクリプトのエラーではなくアプリ全体が止まっていました。どれも安全な数に直すか「大きすぎる」エラーにしました（Studio のテストプレイも同じ）。テストで確かめています。
- **一時停止中の変数表示**: 関数と同じ名前の自分の変数（`count`、`first` など）が、ブレークポイントで止まったときに表示されませんでした。表示するようにしました。
- **ぼうし**: 買わなくてもかぶれていたのを、買ってからにしました（N）。

## iPad でのビルドについて

- **以前**: iPad 第9世代で1回6分ほどかかり、3回目で起動（計18分ほど）。原因はメモリ不足とみています。約46,000行を1つのモジュールとしてビルドしていたので、コンパイルの各ジョブがアプリ全体を抱えていました。
- **今回やったこと**（機能・見た目は削っていません）:
  1. **2つのモジュールに分割**: 土台の `AbloxCore`（Studio は `EditorCore` も含む）と、アプリ本体。各ジョブが自分のモジュールの分だけを持つので、メモリの山が小さくなります。
  2. **土台は Foundation だけを読み込む**: 土台の中に SwiftUI・RealityKit・UIKit を読み込むファイルが1つあり、そのせいで土台の全ジョブが重いフレームワークを読み込んでいました。そのファイルを Engine に移しました。
  3. **コンパイルが遅い部分を分割**: ゲーム詳細、セーブデータ、プレイ画面、保護者設定、ショップ、投票、空の描画、ジェスチャー、素材、パーティクル、吹き出し、Studio の差分表示・ブロックカード・ツールバーなど。表示や動きは変わりません。
- **測定**（GitHub の Mac で iOS 向けにビルド。計測用の設定込みなので実際より遅めです）:

| | ビルド全体 | Swift コンパイル合計 | 型チェック合計 |
|---|---|---|---|
| 分割した直後（土台がまだ SwiftUI などを読み込む） | 140秒 | 204秒 | 76秒 |
| 土台を Foundation だけに | 95秒 | 116秒 | 29秒 |

- **iPad がいつもビルドする状態で測り直しました**（同じ Mac で続けて）:

| | ビルド全体 |
|---|---|
| 1回目（iOS 自体の部品の下準備から） | 77秒 |
| 2回目以降の状態で最初から全部 | 34〜40秒 |
| 同じ、デバッグ情報なし（今回入れました） | 28〜31秒 |

  iOS 自体の部品（UIKit、SwiftUI など）の下準備は、iPad では一度済めば残ります。なので、ふだんのビルドは表の2行目の状態です。

- **更新を「変わったファイルだけ」で入れられるように**（設定 → アップデート）: 新しい版を新しいプロジェクトとして入れると、毎回アプリ全体（約46,000行）をビルドし直します。そこで、この iPad にある Ablox のプロジェクトを一度ファイルで選んでおけば、新しい版は**変わったファイルだけ**をそのプロジェクトに書き込むようにしました。Swift Playgrounds は変わったところだけをビルドし直すので、数ファイルの更新なら数秒〜十数秒で済むはずです。

- **Studio**: 今回はじめて Mac で iOS 向けにビルドし、前からあったビルドエラーを2つ（地図アシスタント、公開シート）見つけて直しました。
